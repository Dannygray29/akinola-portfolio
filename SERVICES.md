## Delivery process

1. Send the repository URL and a concise description of the problem by email.
2. I review the issue and confirm whether it is within scope.
3. We agree on acceptance criteria, price, and payment terms in writing.
4. Work is developed on a separate Git branch.
5. I submit a pull request with a summary and actual test results.
6. You review the changes and approve the agreed payment after acceptance.

## Working standards

- No fabricated experience, client history, test results, or delivery claims.
- Existing licenses and attribution are respected.
- Secrets, passwords, API keys, and customer data are not requested.
- No production changes without an agreed rollback or backup plan.
- If a task cannot be verified with the available environment, that limitation is stated clearly.
- No paid APIs, subscriptions, or other expenses are introduced without prior agreement.
